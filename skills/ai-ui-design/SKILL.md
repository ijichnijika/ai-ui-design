以明确的设计北极星组织界面，让构图、字体、色彩、素材和交互相互呼应，形成有辨识度的表达。克制是保留最有力量的选择、删除无贡献的元素，不是把所有风格磨成中庸。视觉表现与任务完成分别验收。

方法和评审协议均在本目录内，直接使用宿主提供的文件、浏览、看图、生成与隔离执行能力；不要求加载其他 Skill。相对链接以本文件所在目录解析。

## 核心认知

LLM 本质是下一个词预测器，叠加 RLHF 后天然寻找"符合最多人偏好的安全解"。未经调教的模型在设计决策时必然输出蓝紫渐变、居中圆角卡片与通用图标等"委员会设计"。**设计的核心任务是强行将模型推离其可预测区间**。具体手段：

- **外部熵注入**：提示词中说"随机""独特"无效，模型只会吐出词义符合"随机"的高概率套路。从模型外部强制注入真随机字符串（如 `openssl rand -hex 16`），强迫模型基于种子推导色板、排版与布局。
- **无状态 Critic 闭环**：编码智能体存在自利偏误，无法客观评价自己的界面。通过 `invoke_subagent` 调起独立 `design_critic` 子智能体，仅接收浏览器真实渲染截图与参考基准图，严禁提供代码与历史对话，严禁向 Critic 透露及格分数门槛。
- **残忍删减**：AI 天生偏好做加法（光效、渐变、边框、嵌套容器）。高级审美建立在做减法上：主动剔除非功能性视觉噪音，让留白与真实内容传递力量。
- **多模态资产融合**：纯 CSS 模拟渐变与图形是廉价"AI 味"的重要来源。若宿主具备内置图像生成能力，主动调用生成真实材质；若缺失，向用户说明并请求 API Key，隔离于 `.env.agents`。

## 选择范围

从请求、现有页面和参考资料明确用户、主要任务、真实内容、目标设备与交付形式。仅在缺失信息会改变核心方向且无法合理推断时集中提问；可逆的细节自行决定并简述假设。

| 当前范围 | 路径 |
| --- | --- |
| 单个元素、一处间距、文案或颜色这类小改动 | 直接改，在目标视口看改动处和相邻元素，交付时一两句话说明；不盘点现状、不开方向、不启动评审 |
| 新界面或明确要求重新探索 | 按步骤 1–5 执行；只交付设计说明时止于相应方案，并说明未渲染 |
| 已有方向的深化或局部优化 | 保留方向，从步骤 2 进入，只检查受影响的区域与状态 |
| 存量项目里的精修、局部重构或改版 | 先盘点现有页面、设计变量和共享组件，留基线截图，从源头修改 |
| 截图还原 | 按 [布局与视口](references/layout-and-viewport.md) 的"精准还原"，以参考图为视觉基线，确定参考视口与布局约束后进入步骤 2，不发散新风格 |
| UI/UX 评审 | 按问题读取对应参考，只执行步骤 4 的诊断并交付证据与建议；评审现有界面、不要求重新设计时，用步骤 4 的"给已有界面评审" |

## 1. 探索并收敛方向

方向未确定时读 [设计方向](references/design-direction.md)，按它的顺序走：先定调性（能量、完成度、密度、分量、严肃度五个刻度），再从生成引擎起方向（材质×环境 / 场景 / 角色原型 / 设计运动 / 跨领域借用 / 随机种子），写文案之前先定首屏骨架；多个方向时填方向卡、做差异检验。小样只做首屏和最能体现方向的一两个区块。每个方向在方向卡里写下记忆点：集中发力、让人记住的一两处，不让整页处处及格却没有一处出彩。

### 人机共创与多方向验证

在进入生产级代码前，**严禁 AI 擅自单向闭门编写代码**。必须：
1. **发散启发**：AI 主动提供 6-8 个大跨度、故意省略技术细节的极端视觉隐喻。
2. **引导偏好注入**：主动引导人类表达主观审美反馈（触觉、材质、明确排除的俗气元素）。
3. **轻量小样与对比页交付**：AI 依据选定方向与种子差异，快速生成轻量小样，通过 [风格对比页](references/style-explorer.md) 并排交付（支持键盘盲切、实际尺寸、点选标注与即点即选），供人类在浏览器中真实试玩与比对。
4. **优势拼装与方向锁定**：根据人类实际体验反馈（如"A 的配色 + B 的布局 + C 的操作反馈"），融合收敛为最终生产级规范，方可解锁后续工程编码与审查闭环。

### 外部熵种子注入

需要多套真正差异化的方案时：
```bash
SEED=$(openssl rand -hex 16)
```
指令要求模型将该字符串作为灵感种子，解析其字符节奏与数值特征，映射为独特的调色板、版面比例与意象隐喻。严禁在界面中显示种子字符串。

### 风格对比页

需要实际比较多个小样时，按 [风格对比页](references/style-explorer.md) 使用内置模板和生成器，不每次重新制作对比工具。方向由用户的品味来定，不直接采用模型自己想出的方向。给出简短方向清单或对比页，并附推荐理由，请用户选定方向，再说出具体喜欢和不喜欢哪里。

留下一份简短的设计说明：用户任务、内容与主动作、选定方向、视觉关系、关键状态、设备约束和验收重点。

## 2. 建立视觉与交互结构

根据当前决策按需读取，不预先加载全部参考：

| 要解决的问题 | 参考 |
| --- | --- |
| 视觉层级、字体、色彩、空间、图标、风格统一或减法精修 | [视觉语言](references/visual-language.md) |
| 素材选择、视频与 3D | [素材](references/media.md) |
| 生成配图：让图承担意思、写提示词、和页面接成一体 | [配图](references/imagery.md) |
| 动效手感、界面过渡、首屏动画与滚动叙事、时长与检查 | [动效](references/motion.md) |

新产品同时交代主要内容的视觉层级和关键操作链；不要只完成漂亮的默认状态。营销页面可以表达情绪与品牌，高频工具优先识别效率和操作稳定性。

在构图阶段按 [素材](references/media.md) 判断图像能否承担主信息或情绪重心。需要关键素材时先选定或制作它，再围绕其主体、留白与裁切安排文字和操作；不等布局填满后再补图。

既有项目先复用有效的设计变量、组件和交互习惯。发现既有模式妨碍任务时，修复对应源头；不为一次调整另造设计系统。

### 多模态资产注入

若宿主具备内置图像生成能力（如 `generate_image`），主动调用生成真实 3D 实体、材质纹理与视觉主体，严禁回退为粗糙的纯 CSS 伪拟态。若环境无原生生图工具且设计确需图像资产，主动向用户说明需求并请求 API Key，保存于 `.env.agents`（确保已加入 `.gitignore`），仅在本地构建脚本中读取。

## 3. 制作并取得实际证据

- 先完成代表性页面或关键操作链，检查后再延展。只做局部修改时直接完成相关改动。
- 素材有明确表达作用时才制作；文字、控件与业务信息保持可编辑。
- 示例内容按真实产品的样子写。画面上不出现"示例""待核实""示意图""概念稿""按钮未接入"这类制作说明。不伪造业务成功、客户评价或产品指标。
- 在相关目标视口运行并查看结果。长页检查整体节奏和关键局部，不能只看首屏。
- 在实际阅读尺寸检查中文多行标题、正文、控件和窄屏换行。文字重叠或被裁切时，回到内容和布局修复。
- 截图保存成功不等于已经看过；构建成功不等于视觉或操作已验证。

## 4. 独立评审与修正

新页面、整体改版或影响主要构图的变更，在初版稳定后按 [视觉评审协议](references/visual-review.md) 进行独立评审。局部、低风险修改由主 Agent 检查，不为每个间距调整启动评审者。

### 评审模式确认（主动询问）

进入独立评审前，**主 Agent 必须主动向用户确认本次评审模式**：
- **严格达标模式（严格 ≥9 分）**：要求 Critic 给出绝对客观评分，主 Agent 单向把控 $\ge 9$ 分门禁，未达标则根据整改清单修改并重新提审，最多迭代 3 轮直至收敛。
- **单轮诊断模式（单轮评审）**：仅由 Critic 执行 1 轮高密度专业审查，输出顶尖差距诊断与 3–5 项高价值修改清单，主 Agent 吸收后直接修正交付，不反复打分迭代。

### Critic 审查机制

- 主 Agent 保持设计方向与集成责任。具备隔离和看图能力时，派发无历史上下文的视觉评审子 Agent。
- **门禁隔离**：主智能体单向持有收敛条件（严格模式下"评分 ≥ 9/10 或最多迭代 3 轮"；单轮模式下单轮收官）。**无论何种模式，绝对不要将及格门槛写入 Critic 提示词**，以防评分通胀。多轮迭代中对 Critic 使用完全相同的提示词。
- **信息隔离**：Critic 仅接收当前版本截图、任务约束和必要参考（Moodboard），不看制作历史、代码或旧评分。
- 评审以"这一体裁里顶尖设计团队会怎么做"为参照指出最大差距，并按 10 分制给出当前画面离那个标准有多远。
- 有记忆点是动效时，交给评审者一段录屏或开始、中间、结束三帧。
- 风格开始漂移、意见反复或到达用户预算时，保留当前最合适的版本并说明取舍。

### 给已有界面评审

在已有项目里润色了一整页或多页，或用户要求评审现有界面而没有要求重新设计时，标准是仓库现有的设计规范，没有成文规范时以现有实现和组件为准。只做一轮，不打分。

## 5. 验证与交付

检查深度跟着改动走：新页面做全部检查；小改动只看改动处和相邻元素。

- 对照用户任务与选定方向检查真实内容、代表性视口和改动涉及的状态。
- 修正已发现的可用性、溢出、内容和视觉问题。
- **执行减法**：一页只有一个主角，其余安静；逐区块删一轮文字，只放回删了会影响理解的。减法只删装饰和重复，对象名称、判断依据、当前状态和主动作必须留下。在 100% 和 200% 缩放下看关键区域。
- **排查 AI 味七大特征**：滥用发光与弥散渐变 / 多层圆角卡片嵌套 / 随手粘贴的占位图标 / 全屏文本居中对齐 / 过度解释与空洞文案 / 非标准的自制动效 / 均质化信息排布。只要出现即清除。
- 交付请求范围内的文件或预览，说明选定方向、关键变化、实际验证和剩余项。将设计说明、素材、截图及评审记录放在任务目录，不写进 Skill 安装目录。

## 能力边界

没有看图能力时可以产出设计说明、实现代码或源码层面的检查，但明确"未验证实际视觉"，不生成虚假的视觉评分。没有可运行环境时不能声称交互通过。

没有生成能力时优先使用已有合适素材，或交付明确的素材需求和可用占位版本。只使用任务已授权的服务与配置，不因缺少素材自动接入付费服务；本 Skill 不管理密钥、安装工具或发布网站。
