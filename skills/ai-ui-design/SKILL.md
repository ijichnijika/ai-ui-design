模型默认产出"委员会设计"：蓝紫渐变、居中圆角卡片、通用图标。本 Skill 的每一步都是把设计推离这个**可预测区间**的具体推力。以一个**北极星**组织构图、字体、色彩、素材和交互；克制是保留最有力的选择、删掉无贡献的元素，不是磨成中庸。视觉表现与任务完成分别验收。

相对链接以本文件所在目录解析。按当前决策读取参考，不预先全部加载。

## 选择范围

从请求、现有页面和参考资料确定用户、主要任务、真实内容、目标设备与交付形式。只在缺失信息会改变核心方向且无法推断时集中提问；可逆细节自行决定并简述假设。

| 范围 | 路径 |
| --- | --- |
| 单个元素、间距、文案、颜色 | 直接改，在目标视口看改动处和相邻元素，一两句话交付。跳过方向、评审 |
| 新界面，或要求重新探索 | 步骤 1–5 |
| 已有方向的深化或局部优化 | 从步骤 2 进入，只查受影响的区域与状态 |
| 存量项目精修、局部重构、改版 | 先盘点页面、设计变量、共享组件，留基线截图，从源头改 |
| 截图还原 | 按 [布局与视口](references/layout-and-viewport.md) 锁定参考视口后进入步骤 2，沿用参考图风格 |
| UI/UX 评审 | 只做步骤 4 的诊断，交付证据与建议 |

## 1. 与用户共创方向

读 [设计方向](references/design-direction.md) 并按它走完：调性 → 生成引擎（含外部熵种子）→ 首屏骨架 → 方向卡与差异检验 → 小样 → 用户选定。方向由用户的品味决定：给出方向清单或 [风格对比页](references/style-explorer.md) 并附推荐理由，请用户选定并说出具体喜欢与排除什么。

完成标志：用户已选定（或拼装出）一个方向，且你写下了设计说明：用户任务、内容与主动作、选定方向、**记忆点**、关键状态、设备约束、验收重点。此前只做轻量小样，生产代码从这里开始。

## 2. 建立视觉与交互结构

| 要解决的问题 | 参考 |
| --- | --- |
| 层级、字体、色彩、空间、图标、AI 味自查 | [视觉语言](references/visual-language.md) |
| 素材选择、生图与密钥、视频与滚动随动 | [素材](references/media.md) |
| 生成配图的提示词与背景融合 | [配图](references/imagery.md) |
| 动效手感、过渡、滚动叙事 | [动效](references/motion.md) |

- 交代主要内容的视觉层级和关键操作链，覆盖默认状态以外的状态。营销页可表达情绪，高频工具优先识别效率与操作稳定。
- 构图时先判断哪张图能承担主信息或情绪重心；关键素材先定下来，再围绕它的主体、留白与裁切排文字和操作。
- 真实材质、玻璃、金属、3D 主体交给生成素材，CSS 负责可编辑、需精确响应的部分。
- 既有项目复用有效的设计变量、组件和交互习惯；模式妨碍任务时修复其源头。

## 3. 制作并取得实际证据

- 先做代表性页面或关键操作链，看过再延展。
- 文字、控件与业务信息保持可编辑 DOM。
- 示例内容写成真实产品的样子；画面上只出现产品本身会有的文字（"示例""未接入"这类制作说明属于缺陷）。客户评价、业务成果和产品指标不冒充真实数据。
- 在目标视口运行并查看。长页看整体节奏与关键局部；在实际阅读尺寸查中文多行标题、正文、控件与窄屏换行，重叠或裁切时回到内容和布局修复。
- 看过截图才算验证；构建成功只证明能构建。

## 4. 独立评审与修正

新页面、整体改版或影响主构图的变更，初版稳定后按 [视觉评审协议](references/visual-review.md) 派发**无状态 Critic**。先请用户选择模式：**严格**（≥9 分门禁，至多 3 轮）或**单轮诊断**（1 轮，3–5 条修改）。门槛只由主 Agent 持有。已有界面的评审用协议中的"已有界面"模板：以现有规范为准，1 轮，不打分。局部低风险修改由主 Agent 自查。

风格开始漂移、意见反复或到达用户预算时，保留当前最合适的版本并说明取舍。

## 5. 减法与交付

检查深度跟着改动走：新页面全查；小改动只看改动处和相邻元素。

- 对照用户任务与选定方向，检查真实内容、代表性视口和涉及的状态；修正可用性、溢出、内容与视觉问题。
- **残忍删减**：一页一个主角，其余安静；逐区块删一轮文字，只放回删了会影响理解的。保留对象名称、判断依据、当前状态和主动作。在 100% 与 200% 缩放下看关键区域。
- 按 [视觉语言](references/visual-language.md) 的 **AI 味**清单逐项排查，出现即清除。
- 交付范围内的文件或预览，说明选定方向、关键变化、实际验证与剩余项。设计说明、素材、截图和评审记录放任务目录。

## 能力边界

- 没有看图能力：可产出设计说明、代码或源码层检查，注明"未验证实际视觉"，不给视觉评分。没有运行环境：不声称交互通过。
- 没有生成能力：用已有素材，或交付素材需求与占位版本。只用任务已授权的服务；密钥处理见 [素材](references/media.md)。
