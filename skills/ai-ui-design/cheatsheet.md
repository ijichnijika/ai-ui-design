# 决策速查指南与规则手册 (Cheatsheet)

## 核心决策规则 (Decision Rules)

0. **When 处于项目初期与探索（Discover）阶段，Do 强制暂停一切自主代码生成，主动向人类提供大跨度概念选项并引导其注入主观审美偏好，Because 缺乏人类审美校准的全自动 AI 构想必然退化为平庸的统计均值。**
1. **When 提示词输出千篇一律的蓝紫圆角科技风，Do 运行 Shell 脚本生成 32 位外部随机十六进制字符串作为种子注入 Prompt，Because 大模型自身无法产生真正的随机性，必须引入系统外部熵才能打破概率均值。**
2. **When 初版实现完成准备进入视觉评审，Do 主动询问用户选择“严格 ≥9 分迭代”还是“单轮快速诊断”，Because 严格门禁能冲击极致品质但开销较大，单轮诊断能迅速排查严重缺陷且节约 Token，应由用户依据阶段和预算裁定。**
3. **When 界面需要高级玻璃、金属反光或 3D 悬浮效果，Do 调用生成式图像/视频模型产出透明通道素材而非编写 300 行复杂 CSS，Because CSS 拟态在透视、复杂焦散和物理光影上具有不可逾越的真实度上限，极易暴露廉价 AI 味。**
4. **When 页面初版功能已完备但整体发虚、杂乱，Do 对所有修饰性容器、发光阴影与装饰图标执行残忍删减（Ruthless Subtraction），Because 大模型受安全偏好驱使习惯过度添加，顶级设计的高级感源自留白与克制。**
5. **When 在移动端或桌面端构建复杂交互，Do 优先使用宿主平台原生控件（如 Apple HIG）而非纯自绘按钮，Because 原生规范承载了最成熟的无障碍支持、触觉反馈与用户信任直觉。**
6. **When 界面需要真实物理光影/3D 材质且宿主具备生图工具，Do 主动自动调用内置生图工具（如平台的 generate_image）；若宿主无内置工具，Do 主动向用户索取独立 API Key 并严格隔离于 .env.agents（且必须加入 .gitignore），Because 纯 CSS 伪拟态极易暴露廉价 AI 味，且开发凭据必须做到物理级安全隔离。**
7. **When 交付多个设计方向供用户决策，Do 使用内置脚本生成离线风格对比页进行多方向并排试玩，Because 并排实际画面与真机试玩比纯文本描述能快十倍对齐品味。**

## 阶段决策流 (Design Decision Tree)

```text
[新需求启动]
  │
  ▼
[阶段一：头脑风暴与方向共创 (Pattern 3)]  <──【强制人机协同，严禁 AI 单向启动全站重构】
  ├─ Turn 1: 提出 6-8 个极端概念隐喻（故意省略细节）
  ├─ Turn 2: 引导人类注入触觉、材质偏好并排查雷区
  ├─ Turn 3: 产出轻量候选小样并通过内置对比页 (Pattern 7) 并排交付
  └─ Turn 4: 人类在浏览器真实试玩对比，跨方案拼装优势 ──> 锁定终版生产级 POC
  │
  ▼
[阶段二：工程实现与双智能体审查闭环]
  ├─ 注入外部随机种子 (Pattern 1) + 正式编写生产级组件代码
  ├─ 自动调用内置生图 (Pattern 4) 或索取 API Key 隔离于 .env.agents 生成核心资产
  ├─ 捕获浏览器全保真渲染截图 + 准备 Moodboard 参考基准
  ├─ 【主动询问用户】确认评审模式：
  │    ├─ 选项 A：严格 ≥9 分模式（门禁隔离，最多 3 轮迭代直至达标）
  │    └─ 选项 B：单轮诊断模式（1 轮全面体检，快速吸收修改建议）
  └─ 调起独立无状态 Critic 子智能体 (Pattern 2)
       ├─ [严格模式] 评分 < 9 ──> 输出整改指令 ──> Worker 修复代码 ──> 重新提审 (上限 3 轮)
       ├─ [严格模式] 评分 >= 9 ─> 进入 Deliver 阶段
       └─ [单轮模式] 采纳 3-5 条关键建议修正 ──> 进入 Deliver 阶段
  │
  ▼
[阶段三：残忍删减与最终交付]
  ├─ 排查消除 7 大“AI 味”沉疴
  ├─ 复杂动效/材质替换为多模态资产 (Pattern 5 & 6)
  └─ 原生规范化，向人类交付终稿
```

## AI 视觉异味自查清单 (AI Tells Smell List)

| 视觉异味表现 (Smell) | 根本原因 | 根治操作 (Action) |
|---|---|---|
| **蓝紫弥散渐变** | 模型最安全的科技风默认色 | 强制收敛为单一主色 + 黑白灰中性底，高光仅用 1 处微小点缀 |
| **卡片套卡片 (Nested Cards)** | 模型试图划分模块时的无脑分箱 | 彻底移除外层边框与背景色，改用 `gap-8` 等留白和字阶划分（深度 ≤ 1） |
| **随机拼凑的小图标** | 模型习惯给每行文字配一个无意义图形 | 删去所有装饰图标，仅保留高辨识度的系统级通用符号或直接用字符 |
| **全屏文本居中对齐** | 缺乏排版节奏时的偷懒对齐 | 长段文本与列表强制左对齐，仅保留核心短 KPI 居中 |
| **文字过度解释与废话** | 模型试图用词汇证明价值 | 删去所有形容词修饰，保留“动词 + 数字名词”的紧凑文案 |
| **浮夸的巨大字号** | 误以为大字等于视觉重点 | 标题上限严格限制在 32-36px，副标题紧缩为 13-14px |
| **生硬的纯 CSS 3D 旋转** | 试图低成本炫技 | 替换为静态高清渲染资产或视频插帧平滑随动 |

## 关键参数与度量基准 (Thresholds & Defaults)

- **Critic 模式与门禁隔离**：主智能体在评审前主动向用户确认模式。严格模式单向持有 $\ge 9/10$ 分与最多 3 轮上限；单轮模式仅执行 1 轮。**严禁将任何门槛写入 Critic 提示词**，防止打分通胀。
- **Critic 提示词一致性**：多轮审查必须复用完全相同的审查指令；每次均需附带 3-4 张真实商业设计参考图（Moodboard）建立客观对比基线。
- **Critic 资源消耗预算**：Critic 的 Token 消耗应严格控制在总交互 Token 的 **10%** 以内。
- **界面色彩收敛法则**：全局主视觉色不超过 **1 种**；功能辅助色（成功/告警）严格就绪触发；背景色保持中性纯色或微噪点底。
- **容器嵌套层级深度**：界面主要视口内绝对禁止超过 **1 级** 视觉容器嵌套（页面底为 0 级，卡片为 1 级，禁止卡片内再开圆角背景框）。
- **最小触控热区规范**：移动端可交互元素必须保持在 **44×44 pt** 以上，外边距留白不低于 **16 pt**。
