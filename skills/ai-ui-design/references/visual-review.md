# 视觉评审协议

## 评审模式与主动确认机制

在启动独立评审前，**主 Agent 必须主动向用户确认本次评审模式**：
- **严格达标模式（严格 ≥9 分）**：主 Agent 单向把控 $\ge 9/10$ 分门禁，未达标则根据整改清单修改并重新提审，最多迭代 3 轮直至收敛。
- **单轮诊断模式（单轮评审）**：仅由 Critic 进行 1 轮高密度专业审查，输出顶尖差距诊断与 3–5 项高价值修改清单，主 Agent 吸收后直接修正交付，不反复打分迭代。

## 评审者的独立性与无状态隔离

选择能实际看图的隔离执行者（通过 `invoke_subagent` 调起独立的 Critic 智能体，推荐选用高审美高参数的 `Model: "pro"`）。

- **无状态隔离（Stateless）**：每次评审使用全新上下文。只传当前版本的必要证据，严禁继承制作对话、思考过程或旧评审记录。
- **信息物理阻断**：严禁向 Critic 提供前端源码、实现细节或开发借口，防止同情代码复杂度和产生自利偏误。
- **门禁隔离原则**：主智能体（Worker）单向把控收敛判定（严格模式下单向持有评分 ≥ 9/10 分或最多 3 轮上限；单轮模式下单轮收官）。**无论选择哪种模式，绝对严禁将"达到 9 分才合格"写入 Critic 提示词**，以确保其打分的绝对客观与严苛，杜绝评分通胀。

## 交接内容清单

| 提供给 Critic | 绝对不提供给 Critic |
| --- | --- |
| 用户任务、受众、交付范围和目标设备 | 制作者的论证、实现难度与已经投入的时间 |
| 已确定的方向、品牌与不可改变约束 | 前端源码、DOM 结构与技术实现借口 |
| 当前版本渲染截图，注明页面、状态与逻辑视口 | 旧版本截图、旧评分和旧评审记录 |
| 3-4 张对标领域的专业商业设计参考图（Moodboard） | 预设问题清单、希望评审者赞同的诱导性答案 |
| 记忆点是动效时，提供 3–5 秒录屏或关键三帧（起/中/止） | "达到 9 分才合格"等通过性门槛提示 |

## 审美三阶阶梯与情绪板锚定

- **劣质（Bad）**："判断页面是否好看、有没有 AI 味" —— 纯主观，评分剧烈波动。
- **中等（OK）**："评估所追求的美学，设想顶尖设计工作室会如何落地，以此为标尺衡量品质差距" —— 建立了概念框架，但缺乏物理锚点。
- **卓越（Great - 推荐）**："提供 3-4 张行业顶级真实案例图（Moodboard）与 1 张待审截图，要求 Critic 对照基准进行品质排序与差距诊断" —— 具备物理基线，将主观审美品味转化为具体的多图对比。

## 可直接使用的 Critic 评审任务模板

```text
你现在担任国际顶级设计工作室（如 Apple / Pentagram 设计团队）的设计总监。
这是当前界面的真实渲染截图：[待审截图路径]
这是该美学流派的专业参考基准案例图（Moodboard）：[参考图路径1, 路径2...]
用户核心任务与约束：[任务简述]

请依据以下指引进行绝对客观的专业审查：
1. 对照基准与风格定位：对照参考基准评估整体美学方向，设想国际顶级设计团队会如何执行该风格，对比指出当前设计的最大核心差距（1–3 处）。
2. 兼顾宏观与微观：既要从宏观审视全局结构、构图张力与负空间节奏，又要深究字体紧致度、对齐与边距等微观精密细节。如果是后台或高密度工具，重点审查一屏能看到几个对象、主动作离当前对象有多远。
3. 严惩 AI 模板与过度雕琢：排查画面中是否出现过度发光、无意义的多层圆角卡片嵌套、通用占位图标、空洞居中文案、重复线框或画面上的制作说明（如“示例”“未接入”），一旦发现予以严厉扣分。
4. 鲜明大胆有态度：拒绝中庸安全或模棱两可的评价，给出极具专业品味的主见。如果画面处处及格但没有一处让人记住，明确指出最值得集中发力做极致的一两处位置。
5. 反馈紧凑精炼：给出具体、可执行的 3–5 条修改指令，拒绝散文式的虚词废话。
6. 绝对客观打分：给出 1-10 分的分值，精确度量当前设计距离顶级商业基准的真实差距。
```

## 给已有界面评审

在已有项目里润色界面时，评审的标准是这个产品自己的设计规范，不是评审者心里的理想风格。

### 适用场景
润色了一整页或多页、做完局部重构之后，或者用户要求评审现有界面、没有要求重新设计时。单个元素的小改动不评审。只做 1 轮，不打分。

### 先确定规范
1. **有成文规范时以它为准**：设计系统文档、Token 变量文件（颜色、字号、间距、圆角、阴影）、组件库文档。
2. **无成文规范时提取现状**：阅读现有样式配置和共享组件，整理一份简短的现状规范（字阶、颜色用途、圆角间距、关键组件样式）。
3. **交给评审者**：当前版本截图 + 规范摘录 + 不能动的清单（品牌色、字体、全局导航）+ 用户任务。不给源码与历史。

### 已有界面评审任务模板

```text
根据提供的设计规范、不能改动的清单、用户任务和当前画面，评审这个已有界面。
第一部分：逐条列出画面偏离规范的地方（用了规范外的颜色/字号/间距/圆角，同类组件样式不统一，未复用现有共享组件）。
第二部分：在规范范围内指出最影响完成度的 3 处问题，依据是视觉层级、对齐、留白、文字、状态和做减法。每条建议都要能用现有的设计变量和组件做到。
另外列出可以直接删掉的冗余文字与细节瑕疵。
只提供诊断与具体调整方向，不修改代码，不打分。
```
